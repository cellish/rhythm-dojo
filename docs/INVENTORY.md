# INVENTORY — リズム道場（rhythm-dojo）

書法コアの検討用の一覧。2026-11-20 時点の `index.html`（2544行）を読んで確かめた内容。行番号はこの時点のもの。

**先に結論**：このアプリは「リズム（時刻・拍）」が中心で、**楽譜表示・声部・和音記号・規則判定は持っていない**。書法コアと重なるのは「MIDI番号の音高」「Web Audio の音の合成と再生」「拍・小節の時刻計算」「localStorage の保存」くらい。

## 1. 概要

- **アプリ名**：リズム道場（Rhythm Dojo）
- **目的**：キーボード（スマホは画面のパッド）で叩いてリズム感を練習する。1打ごとのずれを ms で測り、結果をカード・メーター・グラフで見せる。
- **主な機能**
  - 4編・22モード（`EDITIONS`, 1770行）
    - 入門編 `MODES`：一定拍、消えるメトロノーム、チェンジアップ、ポリリズム、リズム模倣、テンポ変化の聴き分け
    - クラシック編 `CLASSIC_MODES`：ルバート、付点・複付点、ヘミオラ、変拍子、入り（指揮）
    - ジャズ編 `JAZZ_MODES`：スウィング・フィール、クリックを減らす、ノリの位置、コンピングのリズム、重ねリズム
    - ポップス・ラテン編 `POP_MODES`：16ビート、シンコペーション、ハーフ／ダブル、シャッフル ⇄ イーブン、ラテン、キックになる
  - 易しい順の練習ステップ（`STEPS`, `renderSteps`, `applyStep`）。80点以上でクリア
  - 遅延補正（`calibPlan`, `runCalib`）、叩いた音の選択（`TAP_KINDS`, `percussion`）
  - 結果：スコア、カード、ひとこと、メーター、区分ごとのグラフ（`renderResult`, `groupChart`, `drawChart`）、最近の記録（`renderHist`）
- **言語・フレームワーク**：素の HTML・CSS・JavaScript。フレームワークなし、ビルドなし、モジュール分割なし。
- **公開方法**：GitHub `cellish/rhythm-dojo`（`main`）。Claude のアーティファクトとしても公開（slug `dc17a19e-…`）。GitHub Pages の設定ファイルはリポジトリにない（Pages で公開しているかは未確認）。
- **ファイル構成**

## 2. 音楽データの表し方（最重要）

### 音高

- **MIDI番号（整数）**で持つ。変換は `midiF(m) = 440·2^((m−69)/12)`（363行）。
- **音名・臨時記号・異名同音の区別はない**（C♯ と D♭ はどちらも同じ番号）。音名を表示する場面もない。
- ただし**単位が混在**している：
  - MIDI番号：`pluck(t, midi, kind)`, `piano(t, m, g)`, `BLUES`, `CPROG`, `melNote`, `chordTones`, `leadNote`
  - 周波数（Hz）：`SOUNDS` の `f`（例 `beat:{f:1046}`）、`kick`, `snare`, `conga(t, 220, …)`, `percussion` の各打楽器
  - `playSound(t, name, freq)` の第3引数は、名前によって MIDI番号・MIDI番号の配列・Hz のどれにもなる（304行）。

### 音価・拍・小節

楽譜上の音価（4分音符など）を表す型はない。すべて**時刻（秒）**か**拍の中の位置（小数）**で持つ。

- 練習の1回分は `Plan`（475行）。時刻は開始からの秒。
  ```js
  { bpm, events:[{t, sound, f}],          // 鳴らす音
    targets:[{t, layer, win, group, ...}], // 判定する打鍵（win＝判定の窓、秒）
    segments:[{t, text, sub, cls}],        // 画面の文言
    vis:[{t, row, idx, show}], rows, layers, dur, shade, bands, onTick?, arcs? }
  ```
- 1拍の長さ `spb = 60/bpm`、1小節 `bar = 4*spb`（3拍子・変拍子のモードは各 build の中で別に計算）。
- 小節の作り方は伴奏の部品ごとに別々：`addBar`（クリック）、`jazzBar`（872行）、`pianoBar(p, times)`（1229行、拍の時刻の配列を受け取る）、`groove(p, t, spb, style)`（1465行）。
- リズムの型の書き方が**モードごとに4通り**ある（食い違い）：

| 書き方 | 例 | 使う所 |
|---|---|---|
| 1拍ごとの拍内位置の配列 | `[[0],[0,.5],[.25,.75],[]]` | リズム模倣 `ECHO_LEVELS`（510行）、`patText` |
| 小節内の拍位置（小数） | `pos:[0,1.5,3]` | `SYNC_PATS`, `LATIN`（2小節は 0〜8）, キックの型 |
| `[拍, 裏か]` の組（裏の位置はスウィング比で決まる） | `pos:[[0,0],[1,1]]` | `COMP_PATS`, `SW_PATTERNS` |
| 8分音符の数の組 | `[2,2,3]` | 変拍子 `c_meter` の `FIX`, `MIX` |

- 文字での表示も3種類：`patText`（●・、528行）、`grid16`（●・、1483行）、`compTxt`（「1 ・ ・ 2&」、900行）。

### 声部

- **なし**。複数の旋律を持つ仕組みはない。
- お手本の旋律は単音を `events` に並べるだけ（`melNote` の音階、`leadNote`）。

### 和音

- コードネーム・ローマ数字・数字付き低音の**表記はどれも持たない**。和音は MIDI番号の配列。
  - ジャズ：`BLUES = [[41,'7'], …, [43,'m7'], …]`（417行。ルートの MIDI番号と、'7' か 'm7' の2種類だけの種類名）。`chordTones()` が3音の配置を返す。
  - クラシック：`CPROG = [[36,[64,67,72]], [41,[65,69,72]], …]`（1223行。[低音, [上3声]] の8小節分）。
- ウォーキングベースは `walk()`（422行）がブルース進行からその場で作る（ルート→和音の音→次のルートへ半音で近づく）。

### 調・転調

- **なし**。ジャズは F のブルース、クラシックはハ長調に固定。移調・転調の処理はない。

## 3. 機能ごとの実装

| 項目 | 有無 | 場所・作り方 |
|---|---|---|
| 楽譜表示 | なし | VexFlow 等は使っていない。リズムは ●・ の文字列で示す（`patText`, `grid16`, `compTxt`） |
| MIDI入力 | なし | `requestMIDIAccess` の呼び出しはない |
| 音の再生 | あり | Web Audio API で合成（下に詳細） |
| マイク入力・音高判定 | なし | `getUserMedia` の呼び出しはない（`PLAN.md` で「決める」としている検討事項） |
| 音程・コード・調の計算 | ほぼなし | `chordTones`（3度は 'm7' なら3半音、それ以外4半音）、`fitBass`（オクターブ移動）程度 |
| 規則の判定と採点 | あり（タイミングのみ） | `evaluate`, `stats`, `gradeOf`, `slopeOf`（2021〜2064行） |
| 課題・問題データ | あり | すべて `index.html` 内の JS 定数（下に詳細） |
| ファイルの読み込み・書き出し | なし | MusicXML・MIDI ファイルとも扱わない |
| 言語切替 | なし | 日本語のみ（`<html lang="ja">`、文言は直書き） |
| 保存 | あり | localStorage（下に詳細） |
| PWA・オフライン | なし | manifest も Service Worker もない（1ファイルで外部読み込みがないので、保存すればオフラインでも動く…（推測）） |
| 著作権表示 | あり | `LICENSE`、`THIRD_PARTY_NOTICES.md`、README の節、画面下の `footer.copy` |

### 音の再生（詳細）

- 入口：`ac()`（AudioContext とノイズのバッファを作る）、`newMaster()`（全体の音量とローパス）、`playSound(t, name, freq)`。
- 予約：`schedule()` が 20ms ごとに、0.15秒先までの `events` を `playSound` で予約する（1936行）。
- 時刻合わせ：`heardNow()`（353行）が `getOutputTimestamp()` で「いま聞こえている時刻」を出し、打鍵の時刻 `evToHeard()` もこれで揃える。
- 合成音の部品

| 関数 | 音 | 方式 |
|---|---|---|
| `playTone` + `SOUNDS` | クリック類 | 発振器＋減衰 |
| `pluck(t, midi, kind)` | ウッドベース、ギター風の伴奏・お手本 | カープラス・ストロング法（`ksBuffer`、バッファを `ksCache` に保存） |
| `piano(t, m, g)` | ピアノ | 倍音6つの正弦波＋ローパス |
| `metal` | ハイハット、ライド | 方形波6つ（ドラムマシン風） |
| `kick`, `snare`, `conga` | ドラム、コンガ | 発振器の音程降下＋ノイズ |
| `ring`, `tone`, `percussion` | 叩いた音（ウッドブロック、クラベス等8種） | 共鳴フィルター＋短いノイズ |

### 採点（詳細）

- `evaluate(plan, taps)`：層（`layer`）ごとに、目標と打鍵の組を「ずれの小さい順」に貪欲に結ぶ。窓 `win` の外は外れ。余った打鍵は `extras`。
- `stats`：叩けた数、平均のずれ、標準偏差、スコア（±20/40/70ms で 100/80/50/20 点、外れ0点）。
- `slopeOf`：打鍵時刻と目標時刻の回帰の傾き → 実際のテンポ（走る・もたる）。
- モード固有の判定は `renderResult` の `if(mode.id === …)` に並ぶ（スウィング比、付点の比、ノリの差など）。

### 課題・問題データ（詳細）

すべて JS 定数。外部ファイルなし。

- モードの定義：`{id, steps, name, title, help, desc, opts:[…], build(o)}`。`build` が設定値 `o` から `Plan` を作る。
- ステップ：`STEPS.<id> = [ST(題, 補足, 設定値), …]`（535行。クラシック・ポップス編は `Object.assign(STEPS, …)` で追加）。
- リズムの型：`VALUES`, `ECHO_LEVELS`, `SW_PATTERNS`, `COMP_PATS`, `SYNC_PATS`, `LATIN`, `GROOVES`。
- リズム模倣は出題をその場で乱数で作る（`gen`。自動レベルのときは `onTick` で1ラウンドずつ追加）。

### 保存（localStorage のキー）

`store.get/set`（262行、JSON、try/catch つき）。

| キー | 中身 |
|---|---|
| `rd.calib` | 遅延補正（ms） |
| `rd.tapkind` | 叩いた音の種類 |
| `rd.tapsnd` | 旧：叩いた音のオン／オフ（`rd.tapkind` がないときの移行用に読むだけ） |
| `rd.edition` / `rd.mode.<編>` | 最後に開いた編・モード |
| `rd.opts` | モードごとの設定値 |
| `rd.step.<モードid>` / `rd.stepbest.<モードid>` | 選んだステップ（自由設定は −1）／ステップごとの最高点 |
| `rd.hist` | モードごとの最近の記録（30件まで） |
| `rd.quiz` | テンポ変化の聴き分けの記録 |

## 5. 共通化の候補

### 他のアプリでも使えそうな部分

| 部分 | 関数 | 理由 |
|---|---|---|
| 音高の変換 | `midiF` | どの音楽アプリでも要る。ただし音名との変換はこのアプリにない |
| 合成楽器 | `piano`, `pluck`/`ksBuffer`, `metal`, `kick`, `snare`, `conga`, `percussion` | 外部の音源なしで鳴らせる。ライセンスの心配がない。和音・旋律の再生に使える |
| 先読みの予約再生 | `schedule` ＋ `events` 配列 | 楽譜の再生（テンポつき）にそのまま使える形 |
| 聞こえている時刻の取得 | `heardNow`, `evToHeard` | 打鍵・MIDI入力のタイミングを測るアプリなら必要 |
| タイミングの採点 | `evaluate`, `stats`, `slopeOf` | MIDI入力で「リズムどおり弾けたか」を測る機能を持つなら使える |
| 結果のメーター・区分グラフ | `groupChart`、`renderResult` の `#gauges` 部分 | 練習アプリの結果表示として汎用 |
| ステップ式メニュー | `renderSteps`, `applyStep`, `rd.stepbest.*` | 設定値の組を並べるだけの仕組みで、題材に依存しない |
| 保存の小道具 | `store` | 短く汎用。キーの接頭辞だけアプリごとに変える |

### このアプリ固有で、共通化しにくい部分

- **モードごとの `build`**：伴奏の作り方（`jazzBar`, `pianoBar`, `groove`）と判定の目標が混ざって書かれている。楽譜データから組み立てる形になっていない。
- **リズムの型の書き方が4通り**（2章の表）。共通化するなら「拍の位置（小数）＋スウィング比」に揃える必要がある。
- **和音の表し方**：`BLUES`（ルート＋'7'/'m7'）と `CPROG`（MIDI番号の配列）が別々で、どちらもコードネームやローマ数字を持たない。書法コアの和音表現とは別物と考えた方がよい。
- **指揮の玉**（`drawCond`, `arcs`）、遅延補正、テンポ変化のクイズ：リズム練習に特有。

## 6. 既知の問題

- **TODO・FIXME コメント：なし**（grep で確認）。
- 使われていない残り物
  - `SOUNDS` の `hat`, `ride`, `bass`, `comp`, `lead`, `tap0`, `tap1`：`playSound` がその名前を先に別の関数で処理するか、もう呼ばれないため、参照されない。
  - 変数 `tapSound`（267行）、`lastPlanMaker`（2066行）、`Q.playing`（2393行）：読む所がない。
- `renderResult` を後から包み直している（2536〜2537行、`_rr`）。グラフの再描画用で、見通しが悪い。
- `playSound` の第3引数の型が名前ごとに違う（Hz・MIDI番号・配列）。
- `c_entry`（入り）は毎回テンポが変わるため `Plan(0)` で作り、あとで `p.bpm = 90` を仮に入れている（グラフの都合）。
- リズム模倣の自動レベルは、判定が1ラウンド遅れて反映される（作りの都合）。
- キーボードでは強弱が付けられないので、ゴーストノートは伴奏で聴くだけ。
- 1ファイル 2544 行で、モードが増えるほど長くなる。
- 音色（ピアノ、ドラム等）は合成のみで、実際に聴いての調整が済んでいない（`PLAN.md`）。
